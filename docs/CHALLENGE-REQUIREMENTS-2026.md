## Reach publication path

The rules permit web apps and any programming language, so Reach's Next.js 16 / Node.js 24 stack fits the stated platform rules. Its SQLite deployment model is a **single application host with a persistent, private writable volume** (`REACH_COMMUNITY_DB`, default `.local/community.sqlite`). Keep HTTPS and the canonical `REACH_APP_ORIGIN`; supervise the app and any selected background workers on the same host/database. This uses the existing design described in [Architecture](ARCHITECTURE.md) and [database operations](PANTRY-DATABASE.md). The database contains private account and communication data: never package it with a source archive or expose it publicly.

For a reviewable demo, keep optional provider-dependent features disabled unless deliberately configured and tested. The app's discovery and planning paths can be shown without live AI or email; make clear in the demo which provider-backed functions are unavailable. If the selected hosting platform only offers ephemeral local storage or requires a serverless/multi-instance design, the current SQLite setup does not fit safely as-is: use a single persistent host or plan and validate a database migration before choosing that platform. This is a practical architecture recommendation, not a CAC hosting requirement.

## Decisions the entrant/owner still needs to make

- Confirm the entrant's school enrollment and U.S.-residency eligibility, chosen district by residence or school attendance, and that the district is listed as hosting. No entrant location or eligibility is inferred here.
- Decide whether this Reach submission qualifies as work created after October 30, 2025, or is a 2.0 entry requiring only new coding to be highlighted. The entrant/team must be able to truthfully claim authorship of the submitted code and technical work; the rules do not define how to attribute prior contributors.
- Name the actual team (maximum four), verify that at least half meet the selected district rule, and ensure each person is submitting only once.
- Prepare a complete AI and external-tool/library disclosure, including which parts each student created and can explain. Do not imply that a person authored work they did not do.
- Resolve the official deadline discrepancy before relying on a submission cutoff, and complete registration and submission in the official portal in time.
- Produce the public 1–3 minute demo video and application answers; ensure the app can be opened for judges and source code can be provided if requested.
