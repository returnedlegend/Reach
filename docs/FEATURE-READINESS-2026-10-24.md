## Recommended first release scope

Publish an English-language, online-required **directory and trip-planning prototype for the researched TX-10 area**. Include the 24 sourced records with visible confirmation/provenance caveats, official coverage overlay, manual location entry, opt-in browser location, map and external directions links. Expose in-app routes or address search only when an operator has deliberately configured the provider and attribution/terms; otherwise show their honest unavailable state. Transit should be labeled as the single dated Route 00 snapshot, with schedule conflicts and no live arrivals. Keep the deterministic planner available; label AI, Google sign-in and email as optional and unconfigured until each has been separately set up and verified. Saved items may be offered with a clear device-local notice. Omit public community exchange and volunteer dispatch from the first release. Do not claim complete geographic coverage, live inventory, guaranteed eligibility/hours, safe accessible routes, live transit, live AI, delivered email, offline access, accessibility certification, or production availability.

## Highest-priority release work

1. **P0 — Operator release gate:** choose and document the deployment owner/host; confirm persistent private SQLite, backups, HTTPS origin, ingress rate limiting, retention/pruning, incident ownership, and a rollback plan. No public deployment is evidenced in the dated docs.
2. **P0 — Product scope and truth labels:** keep launch to directory/planning; put each record’s verification date, coordinate quality and unresolved schedule/access caveats where users can see them. Maintain a correction/reverification process before expanding the directory.
3. **P1 — Provider decision:** choose either disabled-provider handoffs for launch or configure a named search/routing provider, review its terms/attribution and privacy implications, then conduct a separately dated live acceptance check. Keep a manual fallback.
4. **P1 — Release accessibility pass:** test the actual release build with keyboard and at least one screen reader, inspect map alternatives and contrast, and resolve blockers before accessibility claims.
5. **P2 — Optional service enablement:** complete and separately verify Google OAuth, AI policy/configuration, and SMTP sender/relay/worker and monitored reply mailbox setup only if those features are in scope. These prerequisites are independent; passing local fixtures does not satisfy them.
