# AI-assisted navigation verification

This independent review covered the Reach food-access planner's new needs, resource limitations, route/ranking, and guidance interfaces. The only browser server used was the parent-provided loopback development server at `http://127.0.0.1:3090`, backed by `/tmp/reach-navigation-qa/community.sqlite`. AI was disabled, routing was disabled, email was preview-only, and the browser's plan/assist results were explicitly synthetic fixtures. No model inference or real email was used.

## Executed checks

`tests/navigation-independent.test.ts` passed 7/7. Tests verify hard closing constraints despite urgency weighting; routed-option precedence under extreme scoring weights; driving cost and pickup-policy treatment; strict isolation of the AI guidance prompt from origins, household pickup details, profile, contacts, and failure-reason text; fixed selected and alternative IDs; rejection of an out-of-scope emphasized evidence ID; and OpenRouter request budgets and long `Retry-After` handling.

`tests/navigation-flow.spec.ts` passed 6/6 Playwright cases (three flows across mobile at 390 px and desktop at 1280 px). The flows cover a shelter request with no shelter catalog, review-before-apply for AI preference suggestions, and a synthetic driving result with guidance, alternatives, map/card selection, external directions, and itinerary download/print. The shelter and driving result screens had zero serious/critical axe violations; every browser case checked for horizontal overflow. Screenshots are in `docs/evidence/navigation-*.png`, and sanitized HTTP observations are in `docs/evidence/navigation-http.txt`.

Read-only HTTP checks against the isolated server confirmed shelter and prepared-meal requests both return HTTP 200, zero candidates, and explicit unsupported-catalog limitations. With routing disabled, a driving request returned 24 directory candidates but zero outbound routes and zero AI calls; no fabricated route was returned. The disabled-provider assist endpoint recognized only directly stated `shelter` and `today` preferences locally. An extra unknown needs field returned HTTP 400. These checks do not verify provider quality or live routes.

`npx tsc --noEmit` and the independent navigation unit file passed. The parent reported project-wide test/build checks and live route-adapter checks separately. This reviewer did not rerun the production build or reproduce those live provider checks.

Playwright collection under Node 24 initially failed in retained access tests because Node's JSON imports were not preloaded. The test script now starts the CLI with `node --import tsx`; `npm run test:e2e -- tests/navigation-flow.spec.ts tests/access-flow.spec.ts --project=mobile --list` successfully collected all six requested mobile cases. This was a test-harness startup issue; no application or fixture changes were needed, and this collection check did not rerun browser behavior.

## Security and factual limits

OpenRouter tests use only a fake fetcher and fixture model IDs. They verify the server-side call boundary, strict structured response validation, free-model catalog constraints and zero pricing, provider data-collection denial, disabled provider fallback, and bounded requests. Live credentials and quota/billing behavior remain unverified.

The AI guidance interface may only prioritize IDs from deterministic public evidence; route times, availability statuses, costs, service windows, feasibility, and selection are computed outside the model. Raw driving/walking instructions are kept in the deterministic UI, not sent for summary. The tests also ensure an infeasible candidate does not become selected or an alternative when the model emits an invalid ID. Household-size and identification preferences are not treated as proof of eligibility or quantity.

Shelter and prepared-meal catalogs are not verified. Pantry listings do not establish shelter beds or prepared meals. Unknown or dated food availability is not a promise of stock. Driving distances and durations are synthetic in the browser fixture; driving costs, parking and the service entrance remain unknown unless verified independently. Transit schedules remain scheduled data, not live predictions. Do not use the fixture screenshots as travel directions.
